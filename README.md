# アストラ書類自動作成システム

Googleフォームの回答から、顧客別フォルダと行政書士確認用の書類下書きを生成するGASプロジェクトです。外部API、有料API、生成AI APIは本番処理で使用しません。

## 現在の実装範囲

- 本命フォームの13項目を項目名で読み取り
- 入力必須チェックと同意確認
- 住所原文を保持したまま、ハイフン表記などを「要確認」に分類
- 顧客入力住所を編集可能な「書類転記住所」へ暫定コピー
- 住民票等の画像は任意。添付があれば目視照合を促し、未提出でも生成を止めない
- 顧客別フォルダの作成
- 申請内容確認書と必要書類リストの下書き生成
- 業務区分別の初回必要書類候補（判定できない業務は「その他」として警告付きで受付）
- 二重生成防止、最大3回の自動再試行、処理ログ
- 再試行上限に達した行の「エラー」表示とメール通知（放置防止）
- 管理用のステータス列と再生成メニュー
- 生成時の任意PDF化と、確認後のメニューからの手動PDF書き出し
- ローカル自動テストとGAS内セルフテスト

契約書・委任状・見積書・正式な申請様式は、行政書士が確定したテンプレートを追加してから対象にします。現時点のコードは、法的内容や住所表記を推測して確定しません。

## フォルダ

- `gas/`: Apps Scriptへ登録するソース
- `test/`: 住所・入力検査のローカルテスト
- `docs/`: 設計判断、導入手順、受入確認
- `source-package/`: クライアント提供ZIPの原本（Git対象外）

## 導入の最短手順

1. 本命回答シートを開き、`拡張機能 > Apps Script` を開く。
2. `gas/` 内の `.gs` ファイルを同名で追加し、`appsscript.json` も反映する。
3. `プロジェクトの設定 > スクリプト プロパティ` で次を設定する。
   - `OUTPUT_FOLDER_ID`（必須）: 顧客別フォルダの保存先フォルダID
   - `TEMPLATE_FOLDER_ID`（必須）: 差込テンプレートの保存先フォルダID
   - `RESPONSE_SHEET_NAME`（任意）: 回答シート名が「フォームの回答 1」以外の場合のみ
   - `NOTIFICATION_EMAIL`（任意）: 処理エラー時の通知先メールアドレス
   - `RESPONSE_SPREADSHEET_ID`（任意）: 回答シートに紐付かないスクリプトから使う場合のみ
4. `setupAstraSystem` を一度手動実行して権限を許可する。
5. 回答シートを再読み込みし、`アストラ書類システム > セルフテストを実行` を実行する。
6. ダミー回答を1件送信し、シートのシステム列、顧客フォルダ、生成書類を確認する。

初期設定は次を自動で行います。

- システム管理列の追加
- 既存の回答行（処理状態が空の行）を「対象外（導入前）」へマーク
- `処理ログ`、`生成書類管理`、`システム設定` シートの追加
- 仮の申請内容確認書・必要書類リストのテンプレート作成
- フォーム送信トリガーと5分ごとの再試行トリガー作成

導入前から残っている回答を処理したい場合は、その行の処理状態を「未処理」へ変更してください。初期設定は運用開始前に済ませてください。


## 重要な運用ルール

- フォームの質問名は、コードとテンプレートを更新せずに変更しない。
- 回答シート名を変えた場合は Script Properties の `RESPONSE_SHEET_NAME` も更新する。
- 3回失敗した行は「エラー」表示になり自動再試行を止める。原因解消後にメニューの「選択中の回答を再生成」で再実行する。
- PDFが必要な場合は、内容確認後にメニューの「選択中の回答のPDFを書き出す」を使う（`PDF_ENABLED=true` なら生成時にも自動作成）。
- 住所は顧客入力を自動変換しない。住民票・登記簿等と行政書士が照合する。
- `生成済み` は下書き生成済みを意味し、提出可能を意味しない。
- `確認状態` を行政書士が `確認済み` にするまで提出に使わない。
- `書類転記住所` は行政書士が必要に応じて修正し、`住所確認状態` を更新する。
- テストには架空データのみを使う。
- テンプレートの正式文面と必要書類は、管轄・申請区分・取得日を確認する。
