# 現在の要件

更新日: 2026-07-01

## 確定している方針

- 顧客向けフォームは契約前のお問い合わせフォームとして扱う。
- 成約率を下げる入力負担はなるべく増やさない。
- 住民票等の画像提出は任意とし、未提出でも受付・下書き生成を続行する。
- 住所は顧客のフォーム入力をそのまま書類転記住所へ初期入力する。
- 無料住所API、生成AI API、画像認識APIで住民票表記を推測・確定しない。
- 行政書士が必要に応じて書類転記住所を修正し、住民票等がある場合は目視照合する。
- 顧客情報から書類ドラフトを自動生成し、Google Docs上で修正できるようにする。
- 内容確認後、必要に応じてPDFを書き出す。
- 本番の帳票雛形はクライアントが収集・確認して提供する。
- 対象業務は補助金、建設業許可、風営法・深夜酒類の3領域を想定する。

## 現在の実装範囲

- 13項目の初回ヒアリングフォーム
- 顧客別フォルダ
- 申請内容確認書
- 業務別の初回必要書類リスト
- 書類転記住所と住所確認状態
- 任意添付の検知（フォームへ項目が追加された場合）
- 入力検査、警告、再試行、処理ログ

## 未確定・クライアント確認待ち

- 実際に自動生成する帳票の一覧と優先順位
- 各帳票の正式な雛形、管轄、取得日
- 契約書、委任状、見積書の正式文面と差込項目
- 住民票等の任意アップロード質問をフォームへ追加する時期
- サイトへGoogleフォームを埋め込むか、サイト専用フォームを作るか
- PDF化を常時有効にするか、確認後の手動書き出しにするか

## 住所の処理

1. 顧客入力住所を原文のまま保存する。
2. 同じ値を書類転記住所へ暫定コピーする。
3. ハイフン表記等は警告するが、自動変換しない。
4. 行政書士が書類転記住所を必要に応じて修正する。
5. 住民票等がある場合は目視照合し、住所確認状態を確認済みにする。
6. 再生成時は顧客入力原文ではなく書類転記住所を帳票へ差し込む。
